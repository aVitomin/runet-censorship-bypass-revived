# Store and reviewer materials

This directory is for maintainers. Users should start with
[Installation](../user/INSTALLATION.md) or [Support](../../SUPPORT.md).
Current public versions/assets are recorded in
[release-current.json](../release-current.json); dated channel verification and
remaining listing work belong in the [store checklist](STORE_PUBLICATION_CHECKLIST.md).

| Material | Purpose |
| --- | --- |
| [Chrome listing](CHROME_WEB_STORE_LISTING.md), [Firefox listing](FIREFOX_AMO_LISTING.md) | User-facing titles and descriptions in Russian and English |
| [Chrome 1.0 reviewer notes](CHROME_REVIEWER_NOTES_1_0.md), [Firefox reviewer notes](../development/FIREFOX_AMO_REVIEW.md) | Review scenarios, build and limitations |
| [1.0 feature inventory](FEATURE_INVENTORY_1_0.md) | Claims mapped to implementation/evidence |
| [Permissions and privacy](PERMISSIONS_AND_PRIVACY.md) | Store-form justifications |
| [Privacy policy](PRIVACY.md) | Current policy and previous edition |
| [1.1.1 screenshots](../assets/releases/1.1.1/README.md#english) | Versioned images and provenance |
| [Link audit](LINK_AUDIT_1_0.md) | Dated URL checks |

Repository listing drafts do not prove that store text was submitted or published.
Preserve submitted text and historical release evidence. Code, packages, signing
and publication follow the [release process](../development/RELEASE_PROCESS.md).

Use the version-free guide, listing, privacy and permission URLs for new references. Preserve published edition links and use the existing release tag for historical copy. Keep the raw Chrome privacy URL and the current notice identical until the dashboard change is verified.
