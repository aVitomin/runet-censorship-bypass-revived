# 1.0.3 implementation notes

The Chromium ZIP is published. See the [release record](../releases/1.0.3.md)
for exact source, trusted-main validation and independent channel status, and
[release metadata](../../release-current.json) for available installation files.

## Included changes

- Chromium avoids full PAC/ownership reads and unnecessary generation cleanup
  when an Effective configuration has no usable proxy credentials. Durable null
  request bindings still prevent later redirects from using a new configuration's
  credentials. Authenticated requests retain ownership checks.
- Firefox shares one still-running successful site-status verification between
  matching URL/completion events. There is no completed-result cache; explicit
  actions, control changes, loading or another URL require a fresh result.
- Chromium popup and diagnostics explain a proxy sign-in safety lock in English
  and Russian. Applying settings does not clear it; full browser restart starts a
  new session. The diagnostic status contains no request IDs or proxy credentials.
- Both targets collect unused PAC/dataset bodies while retaining references needed
  by Saved, Effective, active requests and recovery. Unresolved journals defer
  collection; failure preserves successful routing/settings operations. Firefox
  retains compact hash history separately to reject replayed data after body cleanup.
- Contributor guidance and maintained engineering instructions are consolidated
  in English. User-facing localization, attribution and historical records remain.

The [user changes and troubleshooting notes](../../user/CHANGES_1_0_3.md) supplement
the existing guide. No new permissions, proxy services, telemetry, dependencies or
minimum-browser requirements are introduced. Save remains separate from Apply;
source refresh and recovery must not activate pending Saved settings or enable OFF.

## Validation and limits

The implementation and exact 1.0.3 candidate were exercised on Windows Chrome
156 and Firefox 159. All trusted-main jobs passed and canonical runtime/source
archives match the locally tested candidate byte for byte. Exact QA boundaries
and hashes are recorded in the [release record](../releases/1.0.3.md).

Chromium controlled-page measurements show fewer full-PAC and storage reads, not
a guarantee that every website loads faster. Firefox checks confirm coalescing of
overlapping events; no universal timing improvement is claimed. These changes
address measured costs related to [issue #115](https://github.com/aVitomin/runet-censorship-bypass-revived/issues/115);
the reporter's environment and remaining symptoms still need confirmation.

Cleanup bounds large unreferenced bodies, not all browser storage: Firefox keeps
one historical hash per distinct dataset. Transaction failure/retry and schema
upgrade were exercised; physical disk exhaustion and every minimum browser/OS
were not. Browser auth caches and established connections may outlive Apply.

Follow [the release process](../RELEASE_PROCESS.md) and
[store checklist](../../release/STORE_PUBLICATION_CHECKLIST.md) for exact-source CI,
canonical artifacts, signatures and per-channel verification. Keep the existing
